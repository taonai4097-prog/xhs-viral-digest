## 0. 困境提炼（报告里的真问题）

| 编号 | 类型 | 困境 | 根因 |
|------|------|------|------|
| D1 | P0 红线 | `run_loop.py`（公开）无条件依赖 3 个被 `.gitignore` 排除的私有脚本 → 第三方 clone 必崩 | 公开代码直接 import 私有模块，没有「内核/扩展」边界 |
| D2 | P0 红线 | 子进程失败被 `run_step()` 吞掉 → 爬取崩了还「软空跑」到人闸，运营在假状态上拍板 | 编排器不检查退出码，也不设超时 |
| D3 | P0 | F→G 断链：`generate` 推飞书依赖缺失脚本 | 同 D1，平台适配器被当成了核心依赖 |
| D4 | P1 | README 还是 V1 心智（`run_baokuan_digest.py --with-llm`/智谱 GLM） | 文档与骨架不同步，无单一信息源 |
| D5 | P1 | smoke_test 只测 V1 模块，抓不到「开箱即死」 | 冒烟/集成测试没覆盖新增件 + 缺失依赖自检 |
| D6 | P2 | H→A 反馈闭环断：发了不回收效果数据喂养下一轮 | 缺「指标回收」适配器 |
| D7 | P2 | 私有脚本 vs 公开仓库边界不清 | `.gitignore` 把被依赖的脚本排除了，却没给可选接口 |

**一句话本质**：项目把「平台/账号专属的私有件」当成了「核心逻辑」来硬依赖，于是公开交付变成了**不自洽的半成品**。企业级解法的核心只有一句话——**把公共内核与私有适配器切开，用接口契约 + 能力探测 + 预检医生接起来**。

---

## 1. 总体解法框架（一个动作解决 D1/D3/D4/D7）

业界在「开源核心 + 私有/平台扩展」上的标准答案是 **Open Core（开放内核）+ Ports & Adapters（端口适配器 / 六边形架构）**：

- **内核（public，永远能跑）**：纯业务逻辑 —— 爬取后处理/归一化、验证管线、热度引擎、选题池推荐、loop 编排。这些不碰任何飞书/小红书 API，只依赖本地文件与接口契约。
- **适配器（private/optional，可插拔）**：飞书多维表格读写、小红书草稿箱、MediaCrawler 爬取驱动。它们实现内核定义的**接口（Port）**，缺了任何一个，内核要么优雅降级（本地 CSV 兜底）、要么明确报错「请安装/配置 X」，绝不静默空跑。
- **能力探测（Capability Detection）**：内核在启动时用 `importlib.util.find_spec` 探测适配器是否存在；存在才装配，不存在给清晰安装提示。
- **预检医生（Preflight Doctor）**：一个 `doctor` 子命令，在长跑前一次性体检（依赖/配置/适配器/凭据），把「clone 即死」提前到「运行前一眼看清」。

> 参考范式：ZOOZ Engineering 的 *Integration Hub*（把第三方 API 包在稳定接口后，核心逻辑永不被供应商世界观绑架）；Go 社区的 `internal/adapters` + `internal/core/ports`（依赖向内）；open-core 的 `core/ + enterprise/` 分层。

## 2. 逐困境解法

### D1 + D3（P0）：开放内核 + 适配器插件化

**企业模式**：Ports & Adapters。内核定义三个接口（Port），适配器去实现：

```python
# core/ports.py —— 公开、稳定、不依赖任何私有模块
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class CrawlResult: note_id: str; title: str; likes: int; collects: int; comments: int; shares: int; published_at: str; author: str

class CrawlerPort(ABC):
    @abstractmethod
    def crawl(self, keywords: list[str]) -> list[CrawlResult]: ...

class ContentStorePort(ABC):
    @abstractmethod
    def upsert_topic_pool(self, rows: list[dict]) -> tuple[int,int]: ...
    @abstractmethod
    def upsert_heat_board(self, rows: list[dict]) -> tuple[int,int]: ...

class DraftPublisherPort(ABC):
    @abstractmethod
    def save_draft(self, title: str, body: str, images: list[str], tags: list[str]) -> str: ...
```

**公开默认适配器（随仓库走，保证能跑）**：`adapters/local_csv.py` —— 实现 `CrawlerPort`（读本地 CSV）、`ContentStorePort`（写本地 xlsx）。这样不依赖飞书也能 `run_loop.py run --store local` 跑通 A→E。

**私有适配器（另仓 / `private/`，被 gitignore）**：`adapters/feishu_store.py`、`adapters/xhs_draft.py`、`adapters/media_crawler.py`。它们实现同一 Port，run 时按需装配。

**能力探测（关键，消灭 D1 红线）**：

```python
# core/di.py
from importlib.util import find_spec
def build_store() -> ContentStorePort:
    if find_spec("adapters.feishu_store") and os.getenv("FEISHU_BASE_TOKEN"):
        from adapters.feishu_store import FeishuStore
        return FeishuStore()                      # 私有适配器在位 → 用飞书
    from adapters.local_csv import LocalCsvStore
    return LocalCsvStore()                        # 否则降级本地 CSV，明确打印提示
```

`run_loop.py` **只 import `core.*` 与 `core/di.py`**，绝不 import 私有文件名。私有文件是否存在，由 `find_spec` 决定，而不是由 `import` 报错决定。→ D1/D3 根除。

### D2（P0）：Fail-Fast + 退出码门禁

**企业模式**：subprocess 三铁律（runebook / devopsaitoolkit / DigitalOcean）：① 列表传参不用 `shell=True`；② `check=True` 或显式判 `returncode`；③ 必设 `timeout`。

**改 `run_step()`**：

```python
def run_step(name, cmd, timeout=600):
    print(f"▶ {name}")
    try:
        r = subprocess.run(cmd, check=True, timeout=timeout,
                           capture_output=True, text=True)
        return r
    except subprocess.CalledProcessError as e:
        print(f"✗ {name} 失败（退出码 {e.returncode}）\n{e.stderr}")
        sys.exit(2)            # 整条 pipeline 立即中止，禁止软空跑
    except subprocess.TimeoutExpired:
        print(f"✗ {name} 超时（>{timeout}s）")
        sys.exit(3)
```

原本「爬取崩了还走到人闸」彻底消失——任一步非零退出码，进程直接 `exit`，运营不可能在假状态上拍板。

### D4（P1）：文档即契约 + 单一信息源

**企业模式**：README 是「入口契约」，必须跟骨架同步；用 `doctor` 命令充当「会自己说话的文档」。

- README 改写为 V3 心智：`run_loop.py run [--store local|feishu] → 人闸 → run_loop.py generate [--draft]`，并明确写清：在哪填 `.env`（`FEISHU_BASE_TOKEN` 等）、关键词、飞书表 token。
- 提供 `.env.example`（占位，不存真值），让新人一眼知道要配什么（12-factor Config 要求）。
- 把 `python run_loop.py doctor` 的输出贴进 README 的「部署前自检」小节，文档与命令同源、不会漂。

### D5（P1）：CI 集成测试 + 契约测试 + 缺失自检

**企业模式**：GitHub Actions 在每次 PR 跑「导入体检 + 冒烟」（fixdeverror / StackOverflow / GitHub Community 的 Python PYTHONPATH 坑）。

新增 `.github/workflows/ci.yml`：

```yaml
on: [push, pull_request]
jobs:
  smoke:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install -r requirements.txt
      - run: python -m pytest tests/ -q          # 升级后的 smoke：含新增 4 模块
      - run: python run_loop.py doctor --ci      # 退出码≠0 即 CI 红，抓「开箱即死」
```

`tests/smoke_test.py` 必须新增：① `analytics/topic_pool/xhs_mvp/compliance` 可导入；② `run_loop.py` 引用的文件**存在性契约测试**（`for f in EXPECTED: assert os.path.exists(f)`）；③ 用 `--store local` 跑通 A→E 一个最小样例。→ 「开箱即死」在 PR 阶段就被 CI 挡下，而非 clone 后才发现。

### D6（P2）：反馈闭环（H→A）回环

**企业模式**：边缘归一化 + 指标回收适配器。

加 `MetricsCollectorPort`（可选适配器 `adapters/xhs_stats.py` 走 `xiaohongshu-mcp get_my_stats` / 或读飞书「账号日报」），把已发笔记的**真实互动数据**（赞藏评增速）回灌 `热度看板` 与下一轮 `选题池` 的 `相对表现R` 基准，形成 H→A 闭环。私人账号数据仍留本机、可脱敏。

### D7（P2）：私有/公开边界的工程落地

**企业模式**：12-factor Config（配置与代码分离）+ 私有子仓库/子模块。

- 公开仓库 = `core/` + `adapters/`（含 local_csv 默认件）+ `ports.py` + `di.py` + docs + `.env.example`。
- 私有件 = 飞书/个人账号脚本 + 真 `.env`，放**独立私有仓库**或 `private/`（git submodule，被 root `.gitignore` 排除）。
- `.gitignore` 改为两段清晰注释：「公开依赖（必须随仓）」「私有被依赖（可选，缺则降级）」，杜绝再出现公开代码硬引用私有文件。

## 3. 推荐目录结构（落地蓝图）

```
xhs-viral-digest/
├── README.md                      # V3 心智入口契约
├── .env.example                   # 占位，不存真值
├── requirements.txt
├── run_loop.py                    # 只 import core.*，编排 + doctor 子命令
├── core/                         # ★ 公开内核，永远可跑
│   ├── __init__.py
│   ├── ports.py                   # 接口契约（CrawlerPort/ContentStorePort/DraftPublisherPort/MetricsCollectorPort）
│   ├── di.py                      # 能力探测 + 装配（find_spec）
│   ├── analytics.py               # 验证 + 热度引擎（已有）
│   ├── topic_pool.py              # 选题池人闸（已有）
│   ├── compliance.py              # 合规（已有）
│   └── normalize.py              # 爬取后归一化（从 run_competitor_crawl 抽出的纯逻辑）
├── adapters/                     # ★ 适配器（公开默认 + 私有可选）
│   ├── local_csv.py              # 公开默认：读CSV/写xlsx，保证 clone 即用
│   ├── feishu_store.py           # 私有：飞书多维表格（private/ 或另仓）
│   ├── xhs_draft.py              # 私有：xiaohongshu-mcp 草稿箱
│   └── media_crawler.py          # 私有：MediaCrawler 驱动
├── pipeline/
│   └── xhs_mvp.py                # 去 GLM 成稿（已具备，迁到 core 或保留）
├── tests/
│   └── smoke_test.py             # 升级：含新增模块 + 缺失文件契约 + --store local 样例
├── docs/
│   └── xiaohongshu-mcp-草稿箱部署指南.md
└── private/                      # ★ gitignore，私有件住这里（或独立私有仓库 submodule）
    └── .env                      # 真值，永不上仓库
```

> 对小团队（1~2 人）的务实取舍：**不必上 DI 容器/插件框架**，用「`find_spec` + 一个 `di.build_xxx()` 工厂函数 + `private/` 目录」就够，这是轻量版 Open Core，开销最小、收益最大。

## 4. 给全栈开发的落地清单（按优先级）

### P0（不修=公开用户仍跑不起来）
- [ ] **抽接口**：在 `core/ports.py` 定义 `CrawlerPort / ContentStorePort / DraftPublisherPort`，把 `run_competitor_crawl` 的归一化逻辑、`push_to_feishu_content`、`plan_of_the_day` 的飞书读写分别重构为「内核纯逻辑 + 私有适配器」。
- [ ] **默认本地适配器**：新增 `adapters/local_csv.py`，让 `run_loop.py run --store local` 不依赖飞书也能跑通 A→E。
- [ ] **能力探测**：`core/di.py` 用 `find_spec` 决定装配哪个 store；私有适配器缺失时降级本地并**打印安装提示**，不抛 `ModuleNotFoundError`。
- [ ] **Fail-Fast**：`run_step()` 改为 `subprocess.run(..., check=True, timeout=..., capture_output=True, text=True)`，非零退出码立即 `sys.exit`，删掉静默吞错。

### P1（交付完整度）
- [ ] **README 同步**：改写为 V3 心智 + `.env.example` 说明 + `doctor` 命令。
- [ ] **doctor 子命令**：`run_loop.py doctor` 自检 依赖/配置/适配器/凭据，输出可操作修复建议；`--ci` 模式任一 critical 即退出码 1。
- [ ] **CI 集成测试**：加 `.github/workflows/ci.yml`，PR 跑 pytest + `doctor --ci`；smoke_test 纳入新增 4 模块 + 缺失文件契约测试。

### P2（锦上添花）
- [ ] **反馈闭环**：`MetricsCollectorPort` + `adapters/xhs_stats.py`，回收已发笔记真实数据回灌 `热度看板`/`选题池`。
- [ ] **边界治理**：`.gitignore` 分「公开依赖/私有被依赖」两段注释；私有件迁入 `private/` 或独立私有仓库。

## 5. 验证标准（SMART，验收即此）

| 修复项 | 可验收的判定 |
|--------|--------------|
| D1/D3 根除 | 全新 clone（无 `private/`、无真 `.env`）`python run_loop.py run --store local` **能跑通 A→E**；`run_loop.py` 源码 grep 不到 `import run_competitor_crawl / push_to_feishu_content / plan_of_the_day` |
| D2 根除 | 故意让某阶段脚本 `exit 2`，确认 `run_loop.py` 在**该阶段即中止**、不会打印「人闸待拍板」 |
| D4 同步 | README 首屏是 V3 入口；`doctor` 输出与 README「部署前自检」一致 |
| D5 守住 | 在 PR 里删掉一个被依赖文件，CI 必须**变红**（doctor --ci 退出码 1） |
| D6 闭环 | 已发笔记的赞藏评能回灌 `热度看板` 的 `相对表现R` 基准 |
| D7 边界 | `git ls-files` 不含任何真 `.env`/隐私脚本；`.gitignore` 两段注释清晰 |

## 6. 风险与权衡（红队视角，提前说清）

1. **Open Core 带来少量样板代码**（接口 + di 工厂）。对小团队是开销——所以建议「轻量版」（`find_spec` + `private/` 目录），不上 DI 框架，避免过度工程。
2. **降级到本地 CSV 不等于真飞书**：运营在 `--store local` 下看到的是本地 xlsx 效果，与飞书表是两份数据。需在 README 明确标注「本地模式仅演示/自测，正式运营用 `--store feishu`」。
3. **doctor 可能「假绿」**（agentpatterns.ai 指出）：自检只验「文件在/配置解析对」，验不了「飞书 token 是否真有该表权限」。需配合一次真实 `--store feishu` 冒烟（CI 里用 secrets 跑最小样例）才能真正守住。
4. **私有适配器独立仓库会增加协作步数**（全栈开发需同时拉两个仓）。权衡后推荐 `private/` 子目录 + git submodule，比完全独立仓库更易上手。
