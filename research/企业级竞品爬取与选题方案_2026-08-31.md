> 范围与口径（已与用户确认）：**仅小红书**；**标杆付费栈 + 免费本地替代双轨**；本文件是「方法论 + 可落地规范」，先给方案，**不实现**，后续交全栈开发落地。  
> 现有资产可复用：本项目已有 `pipeline/run_competitor_crawl.py` + `media_crawler_config.yaml`（MediaCrawler 封装）、飞书多维表格 v2 三表（竞品爆款库 / 内容流水 / 账号日报）。本方案在它们之上做科学化与中台化。

## 0. 一句话结论

- **爬**：企业科学爬取 = 分层架构（采集→清洗→存储→分析）+ 反爬克制（代理池/CDP 复用登录，而非破解签名）+ 公开数据边界 + 验证管线（完整性/反刷量/三角校验）。
- **热度**：别看虚荣指标。2026 小红书算法（星云 5.0）真金白银考核的是 **CES（收藏/评论/转发/关注/截图保存权重远高于点赞）+ 自然搜索流量占比 + 相对同赛道的互动表现**。热度分要用**对数归一化 + 相对表现(R) + 时间序列增速**，不能只看绝对值。
- **选题**：企业不是「爬完就写」，而是 **human-in-the-loop**：Agent 把信号整理成「可判断事件 + 推荐理由 + 指数」，人复核拍板，才进入文案生成。工具上付费标杆是千瓜/新红/灰豚，免费替代是搜索下拉词 + 评论区挖掘 + 飞书选题池。

## 1. 竞品怎么爬比较科学（含验证）



### 1.1 企业级采集架构（参考 MediaCrawler 的工程范式）

MediaCrawler（NanmiCoder，开源 57K★）的企业化架构已被多家机构验证，核心是**抽象层 + 工厂 + 代理池**：

| 层   | 职责       | 企业级要点                                                                               |
| --- | -------- | ----------------------------------------------------------------------------------- |
| 采集层 | 按平台拉数据   | 小红书用 **Playwright 无头浏览器**，优先 **CDP 模式复用已登录浏览器会话**（比破解 `_signature` 更稳、更合规）；不要每轮重新扫码 |
| 反爬层 | 代理 + 限频  | **代理池**：企业级建议维持 500+ 高匿 IP，P95 延迟 < 500ms，IP 被封 300ms 内切换；单 IP QPS ≤ 2，设置合理请求间隔     |
| 清洗层 | 去重 + 完整性 | MediaCrawler 内置：去重、必填字段完整性检查、异常重试、格式校验                                              |
| 存储层 | 落地       | 小项目 SQLite/CSV/JSON；企业并发用 MySQL/MongoDB。本项目先用 CSV/JSON 落 `pipeline/` 再同步飞书即可        |
| 分析层 | 对外 API   | 标准接口供上层（热度引擎、选题中台）调用                                                                |

> 关键认知：**反爬的「度」决定合法与否**。用代理池 + 限速 + CDP 复用登录 = 合规友好；**破解加密参数/逆向签名绕过平台防护 = 刑事红线**（见 1.4）。企业稳妥做法是「克制地采公开数据」，而不是「攻破平台」。

### 1.2 付费标杆 vs 免费本地替代（双轨对照）

| 能力        | 付费标杆（企业标准）                                                                        | 免费本地替代（本项目可跑通）                                            |
| --------- | --------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 竞品笔记/达人数据 | **千瓜**（内容深度、爆款拆解、CES 评分、笔记诊断）、**新红**（行业月报/榜单）、**灰豚**（投放分析）、**蝉小红**（商业笔记分析）、**艺恩** | **MediaCrawler** 自采（18 字段：标题/正文/标签/话题/点赞/收藏/评论/分享/作者/粉丝等） |
| 热词/搜索量    | 千瓜热词、新红关键词、5118 长尾词                                                               | 小红书搜索栏下拉词（脚本抓取）、第三方免费试用额度                                 |
| 自家真实数据    | **蒲公英**（真实阅读量、粉丝阅读占比、合作曝光区间）、**聚光**（投放转化，免费）、**薯条**（自然流量测试，免费）                    | 小红书创作者中心后台导出                                              |
| 定制批量      | 极致了数据（按量计费 API，合规定制采集）                                                            | MediaCrawler 自定义关键词/对标账号批量采                               |
| 中台承接      | 各平台 SaaS 看板                                                                       | **飞书多维表格**（你已有 v2 三表）                                     |

> 建议：**以免费 MediaCrawler 为主跑通闭环，把千瓜/新红作为「付费标杆」用来校验你的本地热度分是否合理**（三方估算 vs 官方/付费口径对不上时以官方为准）。

### 1.3 怎么验证（数据保真 + 反刷量）

企业验证不是「采到就行」，而是四道关：

1. **字段完整性校验**：必填字段（笔记ID/标题/点赞/收藏/评论/发布时间/作者）缺失即标记异常、重试或丢弃。
2. **反机器流量（刷量识别）**——真数据 vs 假数据的特征：
   - 假：点赞与收藏**几乎同时发生**、时段集中在**凌晨 2–5 点**、**主页访问率 < 1%**、评论区只有「来了/不错」模板句、无真实场景讨论。
   - 真：互动随时间自然增长、有长评论（>15 字）、主页访问与涨粉正常。
3. **三角校验**：本地爬到的互动数 ↔ 千瓜/新红估算 ↔ 蒲公英官方口径。三方口径天然有误差（样本库≠全量），**对不上时以官方蒲公英为准**，并据误差反向校准本地采样偏差。
4. **同赛道相对校验**：单篇绝对值无意义，要看「该笔记互动 / 同赛道同期均值」的**相对表现 R**。R 异常高（如 >50×）需人工复核是否刷量或极端爆款。

### 1.4 合规红线（必读，企业级不可省）

依据《网络安全法》《数据安全法》《个人信息保护法》及 2025–2026 司法实践：

- **只采公开数据**：笔记标题/内容/点赞/收藏/评论等公开展示信息合法；**禁止采私有数据**（手机号、私信、粉丝列表、浏览历史）。
- **不破解、不逆向**：突破加密验证、伪造请求、破解验证码 = 可能触犯「非法获取计算机信息系统数据罪」。用 CDP 复用登录会话、遵守 robots、限速，是免责基础。
- **频率克制**：单 IP QPS ≤ 2，控制并发，避免对服务器造成负担。
- **数据脱敏 + 留存授权**：含用户昵称/头像等可识别信息做哈希脱敏；保留采集配置、访问日志、授权记录备查。
- **真实判例警示**：常州某网络公司爬小红书数据获利 653 万元，责任人获刑；2025「小红书诉某网络公司案」认定平台用户数据 = 具商业价值的数据集合，批量搬运构成不正当竞争。**「公开 ≠ 可自由商用」**。
- **用途限定**：采集数据用于自身分析/选题，不做「实质性替代」原平台的服务，不转卖。

## 2. 热度信号怎么分析才真实有效

### 2.1 先搞懂 2026 小红书算法（星云 5.0），再定义「热度」

2026 算法已从「流量分发」转向「价值内容筛选」：

- **搜索流量占比 50%–65%+**（高客单行业 >65%）：用户主动搜「解决方法」成主流，内容必须搜索导向。
- **反内容同质化**：4 层漏斗（召回→粗排→精排→重排），重排阶段压低同质化、鼓励原创/AI 标识。
- **新人/中小号获流量倾斜**：0 粉与百万粉初始曝光机制一致，**粉丝数不再决定初始流量**。
- **互动考核重真实性**：前 2 小时高权重互动、长评论、真实截图保存有额外加持。

**CES（Community Engagement Score）2026 公式**（直接决定流量分配）：

```
CES = 关注×8 + 评论×4 + 转发×4 + 点赞×1 + 收藏×1 + 截图保存×6 + 深度阅读×3~5 − 刷量减分
```

> 关键解读：**截图保存（6 分）> 关注（8 分，但门槛高）> 评论/转发（4 分）>> 点赞（1 分）**。纯刷赞毫无用处；**收藏/截图 = 「有用」的极强信号**。

**流量池阶梯 + 赛马**：初始曝光 200–500（新号 50–100）→ 前 1 小时/24–48 小时表现决定晋级；**内容质量分 CQS < 60 直接不进池**。

### 2.2 虚荣指标 vs 真实指标（对照 + 行业基准）

| 类别   | 指标                     | 基准 / 说明                 |
| ---- | ---------------------- | ----------------------- |
| ❌ 虚荣 | 粉丝数、总曝光、单纯点赞数          | 2025 起粉丝数已是虚荣指标；曝光≠有效流量 |
| ✅ 真实 | **自然流量占比**             | >60% 健康；低于 15% 基本靠投流续命  |
| ✅ 真实 | **搜索排名覆盖率**            | 品牌词/品类词进搜索前三屏的数量        |
| ✅ 真实 | **互动率** =（赞+藏+评+转）/ 曝光 | 3%–5% 基准，<2% 选题/质量有问题   |
| ✅ 真实 | **收藏率** = 收藏/阅读        | 2% 不错，3%+ 优秀（教程/清单类更高）  |
| ✅ 真实 | **评论率**                | >0.5% 不错，1%+ 强话题        |
| ✅ 真实 | **分享率**                | 0.3%–0.5% 已很高           |
| ✅ 真实 | **涨粉率** = 新增粉/阅读       | 每千次浏览新增 5–10+ 粉为佳       |
| ✅ 真实 | **连接率**（评论/收藏、关注/主页访问） | 反映争议性、人设吸引力             |
| ✅ 真实 | **曝光-点击率**             | <5% = 封面标题与目标用户错位       |

> **曝光 ≠ 有效流量**：一篇曝光 5.2 万但主页访问仅 800、涨粉 23 的笔记，是「划过不看」。判断流量质量看「曝光-点击率」和「点击-互动率」，不只看总曝光。

### 2.3 热度指数怎么算（企业口径 → 本地可复现）

**付费工具的对数归一化思路（值得本地照搬）：**

- **千瓜笔记传播指数** ≈（笔记点赞 / 达人近期笔记点赞均值）×1 +（收藏/均值）×1 +（评论/均值）×4（+ 达人影响力维度）。
- **新榜指数** = 0.4×人气得分 + 0.6×创作得分；创作得分 = 0.5×ln(赞) + 0.3×ln(藏) + 0.2×ln(评)（**对数归一化**抗量级差异，大 V 不会碾压小号）。

**本地简化「热度分（0–100）」算法（给开发的直接规范）：**

```
1. 取同赛道/同周期笔记集合，算各互动量中位数/均值作为基线。
2. 对单篇笔记计算：
   R_赞  = 赞   / 基线_赞
   R_藏  = 藏   / 基线_藏
   R_评  = 评   / 基线_评
   R_转  = 转   / 基线_转
   R_关注 = 关注 / 基线_关注
3. CES_local = R_关注*8 + R_评*4 + R_转*4 + R_赞*1 + R_藏*1   （相对加权，对标官方 CES 权重）
4. 增速 G = (近7日互动增量 / 发布至今互动总量) 的时间衰减系数（捕捉「正在起量」）
5. 热度分 = 归一化( CES_local * 0.7 + G * 0.3 ) → 映射到 0–100
6. 标注局限：本地无「达人影响力/截图保存/深度阅读」字段时，热度分偏低估收藏型爆款，需在飞书标注「估算」。
```

> 真有效的热度信号三原则：**① 用对数/相对值，不用绝对值；② 看相对同赛道的 R，不是绝对数；③ 看时间序列增速，不是单点快照。**

## 3. 企业怎么选题 + 用什么工具

### 3.1 企业选题决策流程（human-in-the-loop，不全自动）

企业（如千瓜/代运营团队）的共性方法论：

1. **信源分层，不把「热」当「事实」**（飞书官方实践）：
   - S0 官方事实源（证明事件发生）→ S1 官方扩散（首发传播）→ S2 社区验证（真实需求/吐槽）→ S3 媒体/内容（二次扩散与机会）。
   - Agent 只负责把分散信号整理成「可判断事件」，**[不替人下结论]**。
2. **531 测评模型**（容错率最高的选题库打法）：
   - 测试期：用 UGC/KOC 内容测爆款潜力 → 筛选期：标记高潜力内容的**核心要素** → 放大期：Top10% 标准化成**选题库标签体系**。
3. **选题五大来源**：
   - 搜索关键词（月搜索量 ≥ 5000 且笔记数 < 5w，避开红海）
   - 对标账号（建 20–30 个：头部看方向、腰部看手法、新号看红利）
   - 平台热点（发生 24–48h 内借势，找「我的赛道 × 热点」交叉）
   - 垂类长尾词、用户评论区（高频痛点 = 现成选题）
4. **好选题公式**：搜索价值（有人搜）+ 共鸣价值（想点进来看）= 双达标才有爆潜。
5. **721 法则**：70% 已验证选题微创新 + 20% 相关延伸 + 10% 全新试错；建「爆款元素库」（封面/标题句式/开头钩子/互动尾句）交叉复用。

### 3.3 飞书内容中台架构（映射到现有 v2 + 企业实践）

企业用飞书多维表格做「自动化采集 ↔ 人工判断」的工作台，核心是**机器字段与人阅读字段分离 + 看板视图 + 人复核闸门**。映射到你现有资产：

| 表              | 定位                    | 与现有 v2 的关系             |
| -------------- | --------------------- | ---------------------- |
| 信源表            | 管爬什么、怎么爬、信源健康         | 新增（关键词/对标账号清单）         |
| 原始信号表          | 每条证据 URL/来源层级/复核状态    | 部分 = 现有「竞品爆款库」         |
| 更新事件表          | 同事件合并，避免重复            | 新增（去重聚合）               |
| **选题候选表（选题池）** | **推荐理由 + 热度指数 + 你拍板** | **新增（你之前 UX 反馈的核心缺口）** |
| 抓取运行表          | 每轮状态/失败/健康            | 新增（运维）                 |
| 热度看板（视图）       | 赛道 Top、增速榜、自然流量占比     | **新增（解决「跑完没告诉我什么火」）**  |

> **关键设计**：飞书不是「让人读整张表」，而是用视图降低认知负担——运营小白只看「选题池（带推荐理由+指数）」和「热度看板」，点 1 个或说「换一批」，**拍板后才触发文案生成**。这正好闭合你之前「我没选好你就做了，浪费资源」的反馈。
