## ① 苏格拉底追问（本质前提）
- **本质**：让一个运营小白能「看懂数据 → 拍板选题 → 拿到成品」，且**零 GLM、零付费、数据不出本机**。
- 我们没在工程层打转（"要不要建表/怎么生图"），而是锚定"人能不能顺畅走完一圈、不浪费资源"。

## ② 第一性原理（剥离习惯）
- **旧习惯**：爬完直接 GLM 出文案+配图（跳步、未选好就做、配图脱节）。
- **还原事实**：运营要的是"知道什么火 + 为什么推荐 + 自己拍板"，不是一堆没选好的成品。
- **砍掉**：自动生成前置、GLM 依赖、在飞书看草稿（改为小红书草稿箱）。

## ③ 扩散-收敛（现实约束收敛最优解）
- 草稿箱：飞书看稿 / 小红书草稿箱(xiaohongshu-mcp) / xhslink 付费 → **收敛：小红书草稿箱（免费开源，先留接口）**
- 爬取：破解签名 / CDP 复用 / 代理池 → **收敛：CDP 复用 + 代理开关 + 不破解（合规红线）**
- 热度：付费 SaaS / 本地引擎 → **收敛：本地引擎（免费可复现）**

## ④ 诺伊曼思维（反向推死因，防战略破产）
1. **飞书同步挂起** → 已发生，已修（批量分块 100/批 + 限流退避）。
2. **GLM 偷偷回流** → 全链路移除；生图默认 pollinations，内容 agent 注入；残留点：`--provider cogview` 仍可选但非默认。
3. **人闸被绕过** → loop 强制停在 E；`generate` 必须 `--inject`（无内容不出稿）。
4. **草稿箱永远不闭环** → 已知，留 `xiaohongshu-mcp` 接口，用户接受"先接口"。
