## 一、流程总览（账号先行版）

```
0 爬账号（crawl_self.py，历史数据=沉默的方向）
   ↓
0.5 入口分流（第一件事：个人 or 企业？）
   ├─ 个人 → 一人全答（不分角色，最快路径）
   └─ 企业 → 问负责人 or 运营 → 按角色只答该答的
   ↓
1 账号现象分析（转方向？哪条互动最高？内容几类？）
   ↓
1.5 信号不足判定（现象分析产出方向信号了吗？）
   ├─ 信号足够 → 继续 2（正常定制问题）
   └─ 信号不足（如：只爬到一个泛词"AI"/无细分/条数过少）
       ├─ 先补信息：主页简介 / 逐条读全文（标签≠内容）/ 互动分布 / 条数够吗
       ├─ 补完仍不足 → 主权题升级为关键路径（唯一方向来源=主理人口述）
       │    └─ 同时用泛词做【最小赛道扫描】→ 给 2-3 个候选细分 + 证据，标"假设待拍板"
       └─ 主理人一句话定方向 → 才启动正式深度调研（方向未定调研无边界=白跑）
   ↓
2 基于账号定制问题 = 固定骨架 + 账号现象追问(挖真信息；主权题按个人1P/企业1E分流)
   ↓
3 分角色回答（见下方"谁能答什么"）
   ├─ 主权题·个人版(1P) → 个人号主理人本人
   ├─ 主权题·企业版(1E) → 企业负责人（含资质题 Q5E）
   ├─ 执行题(2) → 运营可答
   └─ 主理人缺席 → 降级路径（候选+标注，不编）
   ↓
4 深度调研（客观轨：读者/赛道/爆款/规则，独立查证）
   ↓
5 合并 → 《风格框架 vN》（事实 ∩ 口述，假设项显式标注）
```

### 1.5 信号不足判定（展开）

**触发条件**：现象分析后方向信号薄弱——如：只爬到一个泛词（"AI"）、内容无细分、条数过少（<3 有效笔记）、无高互动锚点。

**判定三步（成本从低到高）**：
1. **先补信息，别急着下结论**：
   - 主页简介（主理人自己写的方向声明，最便宜）
   - 逐条读 title/desc 全文——**标签(关键词)≠内容**，真实内容常比标签细分
   - 互动分布：找"相对最高"那条当沉默方向
   - 条数是否够（不够 → 回爬或接受样本局限并明说）
2. **补完仍不足** → 承认"账号数据给不出方向"，**主权题从补充项升级为关键路径**：
   - 明确告知主理人："你的账号数据没有方向信号，我需要你说一句这个号想干嘛"
3. **等主理人开口期间，并行给候选不给结论**：
   - 用泛词做**最小赛道扫描**（不跑全量调研——方向未定调研无边界=白跑）
   - 产出 2-3 个候选细分方向 + 每个一句话证据（赛道有人占吗/头部是谁/账号历史哪条沾边）
   - 全部标注"**假设，待你拍板**"
   - **每个候选各出一篇示范内容**（3 候选 → 3 篇真实形态）→ 打包给主理人对比选，比纯文字候选更容易触发反馈

**铁律**："AI"只是关键词，不是方向。把泛词当方向去跑正式调研，是这步最常见的死法。

## 二、谁能答什么（角色分工，核心修正）

| 场景 | 谁答什么 |
|---|---|
| **个人**（一人全权负责） | 不用分流：Part 0/1P/2 全答，最快路径 |
| **企业 · 负责人**（定方向者） | Part 0 + **Part 1E 企业主权题**（品牌定位/商业KPI/资质）；Part 2 可交运营 |
| **企业 · 运营**（执行者） | Part 0 + **Part 2 执行题**；**Part 1E 转交负责人，禁止代答** |

| 题型 | 内容 | 谁能答 | 禁止 |
|---|---|---|---|
| **主权题·个人版(1P)** | 你是谁 / 人生目标 / 个人诉求 / 怕的线 / 暴露度 | 个人账号主理人本人 | 运营代猜方向 |
| **主权题·企业版(1E)** | 品牌定位 / 商业KPI / 目标客户 / **资质合规** / 出镜策略 | 企业负责人 | 运营代答（尤其资质题） |
| **执行题(2)** | 更新频率 / 内容形式 / 竞品偏好 / 内容侧重 | 运营可答 | — |
| **当篇定位题** | 这篇给谁看 / 想让他看完做什么 | 运营 + 主理人确认 | — |

**入口分流（第一件事）**：问题库开头 Q0 先问"个人 or 企业"→ 个人走 Part 1P；企业再问负责人/运营 → 负责人答 Part 1E、运营答 Part 2。

**企业版独有的关键题**：Q5E（资质与合规状态：执业许可证/医生执业证/聚光双验）+ Q7E（医疗内容资质归属谁）——**企业医疗号的资质答案决定内容边界**，比品牌方向更硬。

**铁律：主权题主理人不答 → 宁缺毋假。** 缺着推进，显式标注"待主理人确认"，绝不让运营编一个方向填进去。

## 三、主理人缺席的降级路径（企业级默认动作）

拿到一个号、定方向的人不在场时，按优先级执行，**任何时候不许硬编人设**：

1. **账号历史数据 = 沉默的主理人**：他发过什么、互动最高是哪条、最近在往哪转——这是他过去用脚投的票，先当默认方向。
2. **给候选，不给结论**：产出 2-3 个方向候选，每个带依据（来自账号什么信号）+ 标注"假设，待主理人确认"。
3. **Show, don't ask**：**给候选的每个方向各出一篇示范内容**（ABC 候选 → 出 3 篇，每篇用该方向的真实内容形态），打包请主理人看/选——人对比着看三个方向的实际内容，比看抽象描述更容易拍板。主理人一句"我要 B 那篇的感觉"胜过 12 题问卷。
4. 主理人任何一句定向反馈回来后：更新口述档案 → 重跑合并（轻量，不必重爬重调研）。

## 四、角色与时点

| 环节 | 谁执行 | 何时 | 产出 |
|---|---|---|---|
| 0 爬账号 | Agent/脚本 | 建档时 + 每季度 | 原始 CSV / 明细表 |
| 1 账号现象分析 | Agent | 爬完即做 | 现象清单（转方向/高互动/内容分类） |
| 2 定制问题生成 | Agent | 现象分析后 | 定制问题集 = 骨架 + 账号追问 |
| 3 分角色回答 | 主理人(主权) / 运营(执行) | 建档时；主权季度校准 | 口述档案 vN |
| 4 深度调研 | Agent（研究） | 建档时 + 每季度 | 赛道调研报告 vN |
| 5 合并出框架 | Agent + 主理人拍板 | 3 或 4 更新后 | 风格框架 vN |

## 五、合并规则（固定优先级）

1. **客观红线 > 一切**：平台规则（2026 医疗新规等）永远压过主观偏好与流量冲动。
2. **主理人明确口述 > 泛化建议**：他说"引流找项目"，就按 to B 信任向，不被爆款套路带偏。
3. **事实 > 印象**：赛道空白位、竞品打法以调研报告为准。
4. **冲突处理**：客观红线→直接改方向；主理人口述与调研冲突→标出交主理人拍板，不静默二选一。
5. **缺主权答案时**：标注"待确认"，用账号数据默认方向先推进 MVP，不阻塞。

## 六、版本与档案约定

- 每账号独立目录 `accounts/<id>/`，三件套带版本号：
  `赛道调研报告_vN.md` · `口述档案_vN.md` · `风格框架_vN.md`
- brand.json（机器可读，成稿工具加载）+ 风格框架 md（人读，运营查看）
- 规则类信息必带查证日期；复跑先核时效（医疗新规=生死线）

## 七、质量门槛（不达标打回）

| 调研项 | 门槛 |
|---|---|
| 账号现象分析 | 必须列出 ≥3 条可观察信号（转方向/高互动/内容构成），不许空泛；**产出信号不足 → 走 1.5 判定，不许硬推** |
| 读者画像 | ≥3 独立信源 |
| 赛道参照 | ≥5 账号（含体量/打法）+ 明确空白位 |
| 爆文解剖 | ≥3 篇真实爆文（封面/标题/结构拆解） |
| 变现路径 | 含最新平台规则查证 + 查证日期 |
