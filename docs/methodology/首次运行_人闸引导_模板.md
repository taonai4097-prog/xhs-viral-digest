# 首次运行·人闸引导（AI 助手 / 新手必读）

> 适用对象：**任何第一次拿到本仓库、被要求"下载并跑通/测一遍/跑一次"的 AI 助手或真人**。
> 制定原因（2026-09-04 事故）：曾有 AI 在全新空目录接到"下载并跑通"后，一口气跑完
> SSH→clone→预检→冒烟→闭环→成稿→评估 全流程，中间**没有一次停下让用户拍板**，还自行
> 往 `accounts/demo/` 写了 brand.json——用户原话："他不动声色的突然自己做了很多人闸的决定"。
> 本文件把规矩写进仓库，任何下载者都能读到，不依赖某个 AI 的私人配置。

## 一句话规矩

**第一次跑 = 一个阶段一个阶段来，每阶段结束停下汇报、等用户说"继续"才动下一步；
只有用户明确说"直接自动跑/以后不用一步步问"了，才允许连续执行。**

## 主路唯一（先读这个，别跑错方向）

本仓库**有且只有一条主流程：账号先行**——先爬「自己的账号」再谈选题，不是先爬竞品。
路径骨架固定不变（换账号/换方向只换内容，不换路）：

```
爬自己的账号(creator,扫码) → 账号现象分析 → 主权题口述 → 深度调研
→ 风格框架+brand.json → 打分卡选方向(候选≥10) → 爬爆款验证
→ 选题池(人闸拍板) → 内容简报(人闸拍板) → 成稿
```

详见 [docs/methodology/README.md](README.md)「0. 主路唯一：账号先行」。
⚠️ demo CSV 只作列格式参考，**不是 run 的合法输入**；正式跑 = 真实爬取自己账号的数据。

## 两种模式

| 模式 | 何时用 | 行为 |
|------|--------|------|
| **A · 首跑引导（默认）** | 用户第一次让跑这个项目，或没说过"直接自动跑" | 阶段化步进：每步做完→汇报→**等用户"继续"** |
| **B · 复跑自动化** | 用户明确说过"跑通过了/以后直接自动跑" | 可连续执行非人闸步骤；**人闸决策点仍必须停下问** |

**拿不准用哪个 = 一律按模式 A。不要因为任务看起来明确就自作主张全自动。**

## 人闸决策点清单（AI 一律不得自行拍板）

1. **任务边界**：这次是"下载跑通 / 回归测试 / 复验 / 搭建新功能 / 纯技术走查"？
2. **使用者身份**：给个人号用，还是企业/多账号用？（决定要不要碰 enterprise 治理分支）
3. **节奏**：首跑引导（A）还是复跑自动化（B）？——由用户选，AI 不得自选。
4. **任何"写文件/建目录/放配置"动作**：例如往 `accounts/<id>/` 写 brand.json、复制文件到项目目录。
   这类动作**必须先单独列出、请用户批准**，绝不能夹在测试流程里"顺手"做掉。
   ⚠️ **demo CSV 红线**：`examples/demo_search_contents.csv` 只是列格式参考，**不是 run 的合法输入**；
   禁止复制进 `tools/MediaCrawler/data/xhs/csv/` 当数据跑。主路唯一：装依赖 → 装爬虫 → 爬真实数据 → run。
5. **结论性判断**（能不能合 main、该不该发版）：只给建议，用户拍板。

## 模式 A 的阶段化步进模板

每完成一个阶段，输出固定格式汇报并**停下**：

```
✅ 阶段 N 完成
- 做了什么：……
- 结果：……
- 发现的问题/风险：……
- 下一步打算：做 X（理由）
- 需要你拍板：……（没有则写"无，等你点头继续"）
```

**禁止在汇报里夹带执行下一步。** 阶段划分示例：
拉代码 → 摸清版本/结构 → 环境预检(doctor) → 冒烟(pytest) → 真实闭环(run --local，停在选题池人闸) → 成稿(generate) → 防御验证(fail-fast/账号铁律) → 黄金十步评估 → 报告。

## 禁止事项（红线）

- ❌ 接到任务直接 clone 开跑，不先确认模式与边界。
- ❌ 自己脑补意图：文件夹叫"测试" ≠ 用户说了"只测试"；仓库旧文档 ≠ 本次窗口的用户指令。
- ❌ 静默做有副作用的动作（clone/写文件/建目录/跑长命令）后不汇报，让用户从结果里自己发现。
- ❌ 在"首跑"里把"写 brand.json / 复制 CSV"这类搭建动作当测试的一部分顺手完成。
